# Build brief: pdfops

Build a Python library "pdfops": reliable PDF operations that an LLM agent calls as tools. Common rules: Python 3.12, works on Windows and Linux. Allowed dependencies only: openpyxl, python-docx, docxcompose, python-pptx, pypdf, pdfplumber, fpdf2, pandas, numpy, jsonschema. No network, no telemetry, no subprocess. Every public operation is a plain function that returns a JSON-serializable report {"ok", "changed", "warnings", "details"} and never raises for user errors. Each ships a JSON Schema in SCHEMAS[name], at most 600 characters. Pytest tests generate their own fixtures with fpdf2. Apache-2.0.

Operations: info (pages, page sizes, text or scanned per page, form or not, encrypted or not, metadata), extract_text (per page, with layout-preserving and plain modes), search (terms or regex, returns page numbers and snippets), extract_pages, delete_pages, split (by ranges, every N pages, or halves), merge (with an optional bookmark per source), append_pages, insert_appendix, rotate, form_fields (name, type, current value, options), fill_form (sets values and NeedAppearances so viewers show them; checkbox and radio states handled; reports unknown field names), flatten_form, tables (pdfplumber table extraction with header detection; merges a table that continues across pages), tables_to_csv, tables_to_xlsx (one sheet per table, numbers typed), scanned_pages (detects image-only pages), drop_blank_pages (near-white image pages and empty text pages), summary_note (adds a cover or end page with given text using fpdf2, matching the page size), replace_name_overlay (covers a found text string with a white box and writes new text in a matching font size; reports where it could not match), letter (makes a one-page letter PDF from fields).

Be honest in reports: when a PDF is scanned and has no text layer, say so; never claim OCR.

Tests: one per operation, including a two-page table, a checkbox form, an encrypted file reported cleanly, and a scanned-page fixture made from an image.
